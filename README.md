# 延迟观战服务

多人比赛的延迟观战视图：权威事件日志 → 延迟释放 → 信息过滤 → 观众。
优化实现按（规则版本， 观战时刻， 信息权限）共享重建结果，全量重建保留为正确性基准。

## 图形入口（主要）

```sh
npm run demo   # 然后浏览器打开 http://localhost:8080
```

页面左侧是玩家实时视角，右侧是延迟观战视角。观战面板提供：

- **观众A / 观众B 切换**：两个独立观众会话（延迟 5s / 12s），共享服务端缓存；
- **拖动时间**：滑块沿延迟窗口回看，服务器返回该观战时刻的快照预览（不越过延迟边缘，不打断跟随流）；
- **共享缓存优化开关**：开 = 优化实现（共享缓存），关 = 基线（每连接全量重建）。两种模式下延迟画面与公开状态应完全一致，运行状态面板显示成本差异；
- **模拟断线重连 / 低速轮询**：触发续传与缓冲不足重建；
- **运行状态面板**：观战时钟、会话状态、缓存请求/命中/增量/全量重建/事件应用/投影、失效原因与最近失效记录、基线重建累计；
- **异常标记**：对延迟画面与公开状态做客户端校验（未来事件、未公开对象、赛程泄漏、结果提前、隐身位置、计分先于原因、计分回退），异常会以红色列出。

## 辅助命令

```sh
npm test              # 全部测试（含优化 vs 基线逐消息对照）
npm run bench:load    # 观众负载发生器：首次加入 / 稳定跟随 / 大量观众同时重连
npm run bench:memory  # 内存测量（堆驻留，缓存有界性）
```

负载发生器的结论只从原始记录计算，记录写在 `bench/out/load-raw.jsonl`，可用
`node bench/load.js --summarize bench/out/load-raw.jsonl` 不重跑直接重新计算结论。

## 缓存设计（src/cache.js）

- **键** = （规则版本 `rulesVersion`, 观战时刻 → 事件序号 `seqAt(T)`, 信息权限 `public` / `team:X`)。
  同一事件前缀覆盖的不同时刻共享一条目；队伍投影与公共投影是不同条目，
  共享缓存不会把队内信息送给公共观众。
- **两层**：权威层（全量状态，仅服务端）从最近的缓存前缀**增量推进**，
  只应用其后的事件、只更新受影响的对象；投影层按权限过滤后分发。
- **有效区间**：条目只在权威日志仍能佐证它时可用（与基线 `rebuildAt`
  的成功条件一致）。保留期淘汰、规则版本变更、容量上限都会使条目失效，
  失效原因计数（`retention_gap` / `rules_version` / `capacity`）。
- **可观测**：`cache.stats` 给出缓存命中之外的真实执行次数（增量推进、
  全量重建、事件应用、投影），性能结论可从原始记录重新计算。
- 观战延迟不变、事件流不裁剪；观众只拉不推，慢观众不会阻塞比赛本身。
